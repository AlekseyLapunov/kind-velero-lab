# K8s Backup and Restore Automation (Velero & S3)

## Описание проекта
Данный проект представляет собой готовое инфраструктурное решение для автоматизации процессов резервного копирования, симуляции аварийных ситуаций и восстановления данных (Disaster Recovery) в локальном кластере Kubernetes (`kind`).

В качестве целевого приложения используется веб-сервис с СУБД PostgreSQL, развернутый на постоянных томах типа `Local Persistent Volume`. Для резервного копирования манифестов и контента файловой системы дисков применяется утилита **Velero** с файловым движком `Kopia`. В качестве целевого хранилища резервных копий поддерживается как локальный S3-совместимый сервер **MinIO**, так и объектное хранилище **VK Cloud Object Storage**.

Проект снабжен набором Bash-сценариев для полной автоматизации резервного копирования с фиксацией и проверкой динамических хэш-сумм (MD5) таблиц базы данных, гарантирующих 100% целостность восстановленной информации.

## Требования и зависимости
Для успешного развертывания и запуска проекта на хост-машине (тестировалось на AlmaLinux 10.2) должны быть установлены следующие компоненты:

* **Docker Engine** (версии 20.10+) — среда контейнеризации для узлов кластера и утилит;
* **kind** (Kubernetes in Docker) — инструмент для развертывания локальных K8s-кластеров;
* **kubectl** — интерфейс командной строки для управления Kubernetes;
* **Helm** — менеджер пакетов для развертывания серверной части Velero;
* **Утилита Velero (CLI)** — клиент командной строки, совпадающий по версии с сервером;
* Доступ к развернутому инстансу **MinIO** или аккаунту **VK Cloud S3**.

## Инструкция по ручному развертыванию стенда

### 1. Подготовка инфраструктуры хранения
Перед запуском приложений необходимо физически подготовить директории на рабочем узле (worker) кластера `kind` для изоляции оригинальных и восстанавливаемых данных, а также применить манифесты PV/PVC:

```bash
# Создание папок внутри контейнера-узла kind
docker exec -it backup-demo-worker mkdir -p /mnt/data-app /mnt/data-restored
docker exec -it backup-demo-worker chmod -R 777 /mnt/data-app /mnt/data-restored

# Применение конфигурации хранилищ
kubectl apply -f k8s/storage.yaml
```

### 2. Развертывание тестового приложения
Создайте пространство имен `app`, секреты авторизации СУБД и примените манифесты инициализации и деплоя:

```bash
# Создание namespace и секретов базы
kubectl create namespace app
kubectl create secret generic demoapp-db-secrets \
  --namespace=app \
  --from-literal=username=postgres \
  --from-literal=password=mysecretpassword

# Применение скриптов инициализации БД и деплоя приложения
kubectl apply -f k8s/postgres-init-config.yaml
kubectl apply -f k8s/demoapp.yaml
```

### 3. Настройка и установка Velero
Создайте пространство имен `velero`, подготовьте конфигурационный файл секретов `helm/s3-credentials` (на базе предоставленного шаблона `s3-credentials.example`) и установите Helm-чарт:

```bash
kubectl create namespace velero

# Создание секрета для доступа к S3
kubectl create secret generic s3-credentials \
  --namespace velero \
  --from-file=cloud=helm/s3-credentials

# Установка Velero из официального репозитория
helm install velero vmware-tanzu/velero \
  --namespace velero \
  --create-namespace \
  -f helm/velero-values.yaml
```

## Автоматизация и запуск сценариев
В директории `scripts/` находятся преднастроенные сценарии для сквозного тестирования цепочки бэкапа и восстановления:

1. Выполнение резервного копирования с фиксацией хэш-сумм таблиц:
   ```bash
   ./scripts/0_create_backup.sh
   ```
2. Симуляция полной аварии (удаление оригинального namespace):
   ```bash
   ./scripts/1_simulate_crash.sh
   ```
3. Восстановление инфраструктуры в новое пространство имен `app-restored`:
   ```bash
   ./scripts/2_restore.sh
   ```
4. Валидация и аудит целостности восстановленных данных:
   ```bash
   ./scripts/3_data_check.sh
   ```
